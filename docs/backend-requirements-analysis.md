## 2. 后端视角分析

### 2.1 是否需要后端服务

**结论：不需要。**

本任务为纯前端静态站点游戏，所有需求均可在浏览器端完成：

| 需求 | 实现方式 | 是否需要后端 |
|------|---------|-------------|
| 游戏逻辑与状态管理 | 前端 GameEngine 模块 | 否 |
| 最高分存储 | 浏览器 localStorage | 否 |
| 难度选择持久化 | 浏览器 localStorage | 否 |
| 输入处理 | 前端 InputHandler 模块 | 否 |
| 页面渲染 | 前端 Canvas/DOM 渲染 | 否 |
| 静态部署 | 普通 HTTP 文件服务 | 否 |

工单明确说明："无需原生 App、小程序、后端服务、账号登录、联网排行榜或多人对战"。PRD 也确认"本任务为纯前端静态站点，无后端服务"。

### 2.2 数据与存储方案

- 游戏状态：运行时内存管理，无需持久化。
- 最高分与难度偏好：localStorage 存储，key 建议 `snake-game-scores` 和 `snake-game-settings`。
- 存储异常降级：StorageService 模块捕获异常，回退为内存存储（刷新后丢失），不阻断游戏。

### 2.3 静态部署方案

构建产物为纯静态文件（HTML + CSS + JS），可由任何静态 HTTP 服务器部署（如 `npx serve dist`、Nginx、GitHub Pages 等）。无需后端运行时。
