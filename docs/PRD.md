## 1. 背景与目标

### 1.1 背景
在 ceshi 空间交付一款产品级 Web 贪吃蛇小游戏 V1，用户通过浏览器即可开始游玩。目标仓库 `https://github.com/peopleyoung/ceshi`（仓库 ID：10001）在发布任务时 main 仅有 README.md，需从零搭建最小可维护的前端项目。

本次任务同时承担数字员工流转验证目的：由产品经理完成需求分析后，按 SDLC 流转至前端开发、测试、代码审查及产品验收等阶段。

### 1.2 目标
- 交付一款操作顺畅、视觉完整、状态反馈清晰的 Web 贪吃蛇游戏。
- 可构建为静态站点，由普通静态 HTTP 服务部署。
- 兼顾桌面浏览器与手机浏览器。
- 代码结构清晰，依赖精简，便于维护与自动化测试。

### 1.3 非目标
- 不开发原生 App、小程序。
- 不实现后端服务、账号登录、联网排行榜或多人对战。
- 不引入无关服务、埋点或外部账号依赖。

## 3. 功能范围

### 3.1 完整游戏流程
- 首次进入：展示游戏说明与开始入口。
- 运行中：蛇按固定间隔在网格上移动，玩家通过输入改变方向。
- 暂停/继续：空格键或可见按钮切换；页面失焦/切后台自动暂停。
- 游戏结束：碰墙或碰自身 → 失败弹层，展示本局得分、该难度最高分、重开按钮。
- 胜利：棋盘填满 → 胜利弹层。
- 重新开始：清除当前状态，以当前难度开始新一局。

### 3.2 经典规则
- 固定网格棋盘（建议 20×20 或类似尺寸，具体由前端实现决定）。
- 吃食物：蛇增长一格，按难度计分规则加分。
- 碰撞检测：碰墙或碰自身 → 游戏结束。
- 食物生成：仅在空格子上随机生成，棋盘填满时触发胜利。
- 反向限制：禁止直接反向移动（如正在向右时不能直接向左）。
- 快速连续输入：同一移动周期内的多次输入需正确处理，不能绕过反向限制。
- 尾格碰撞规则：蛇头进入本步将移走的尾格时，按正确碰撞规则处理（即该尾格已移走，不算碰撞）。

### 3.3 操作方式
- 桌面：方向键（↑↓←→）+ WASD。
- 暂停/继续：空格键 + 可见按钮。
- 手机：可点击的方向控制按钮（上下左右）。
- 游戏区域的方向操作不引起页面意外滚动。
- 其他页面元素保留正常键盘行为（不全局拦截无关按键）。

### 3.4 难度与计分
- 三档难度：休闲、标准、挑战。
- 速度有明显区分（具体数值由前端实现配置，建议休闲 200ms、标准 150ms、挑战 100ms 或类似）。
- 开始后本局难度固定，中途不可切换。
- 界面清晰展示：当前难度、本局得分、该难度最高分。
- 计分及速度配置集中管理（配置文件或常量模块）。

### 3.5 本地记录
- 使用 `localStorage` 保存各难度最高分及用户最后选择的难度。
- 刷新后恢复。
- 存储不可用或数据损坏时仍可正常游玩（降级处理，不阻断游戏）。

### 3.6 状态保护
- 页面切到后台（`visibilitychange`）或窗口失焦（`blur`）时自动暂停。
- 返回后由用户主动继续。
- 反复暂停和重开不会产生重复计时器、重复事件监听或异常加速。

## 4. 产品体验要求

### 4.1 视觉风格
- 统一、精致的现代街机视觉。
- 棋盘、蛇身、食物、得分区、控制区和状态弹层具有清晰层级。
- 开始与失败界面完整，不使用临时占位文案。

### 4.2 响应式布局
- 至少覆盖 360px、768px、1440px 宽度。
- 棋盘与控制区不遮挡、不溢出。
- 触控按钮容易操作（足够大的点击区域）。
- 适配高像素密度屏幕（devicePixelRatio），保持棋盘清晰。

### 4.3 可访问性
- 所有按钮具有明确名称、焦点样式和可用状态。
- 主要流程可通过键盘完成。
- 信息表达不只依赖颜色（如失败提示同时用文字和颜色）。
- 尊重 `prefers-reduced-motion` 系统偏好。

### 4.4 代码质量
- 游戏逻辑与渲染、输入、存储分离，方便自动化验证。
- 依赖保持精简并提交锁文件。
- 正常操作无未处理异常或控制台错误。
- 连续游玩、调整窗口及反复重开时状态与速度保持正确。

## 5. 接口契约草案

本任务为纯前端静态站点，无后端服务。以下为内部模块接口契约，供前端开发参考：

### 5.1 游戏引擎模块（GameEngine）
```
interface GameEngine {
  start(config: GameConfig): void
  pause(): void
  resume(): void
  restart(): void
  changeDirection(dir: Direction): void
  getState(): GameState
  onStateChange(cb: (state: GameState) => void): void
}

interface GameConfig {
  difficulty: Difficulty
  boardSize: { rows: number; cols: number }
}

type Difficulty = 'casual' | 'standard' | 'challenge'
type Direction = 'up' | 'down' | 'left' | 'right'

interface GameState {
  status: 'idle' | 'running' | 'paused' | 'gameover' | 'victory'
  snake: Array<{ x: number; y: number }>
  food: { x: number; y: number }
  score: number
  highScore: number
  difficulty: Difficulty
}
```

### 5.2 存储模块（StorageService）
```
interface StorageService {
  getHighScore(difficulty: Difficulty): number
  setHighScore(difficulty: Difficulty, score: number): void
  getLastDifficulty(): Difficulty | null
  setLastDifficulty(difficulty: Difficulty): void
}
```

### 5.3 输入模块（InputHandler）
```
interface InputHandler {
  onDirection(cb: (dir: Direction) => void): void
  onPauseToggle(cb: () => void): void
  destroy(): void
}
```

## 8. 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| localStorage 在某些浏览器隐私模式下不可用 | 最高分无法保存 | StorageService 做异常降级，不阻断游戏 |
| 手机浏览器触控事件兼容差异 | 方向按钮操作异常 | 使用 pointer 事件 + touch 事件兼容处理 |
| 高像素密度屏幕 Canvas 模糊 | 视觉体验差 | 按 devicePixelRatio 缩放 Canvas |
| 快速连续输入导致反向穿越 | 游戏逻辑错误 | 输入队列 + 每 tick 只处理一个方向变更 |

## 9. 技术选型建议（供前端开发参考）

- 构建工具：Vite（轻量、快速、原生支持 TypeScript）。
- 语言：TypeScript（类型安全，便于模块接口约束）。
- 渲染：Canvas API（性能好，适合游戏渲染）。
- 测试框架：Vitest（与 Vite 生态一致）+ jsdom 或 happy-dom。
- 不使用前端框架（React/Vue 等），保持轻量；纯 TS + DOM/Canvas 即可满足需求。
- 最终选型由前端开发决定并在 README 中记录。
