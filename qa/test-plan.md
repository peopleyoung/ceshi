## 1. 测试目标与范围

### 1.1 目标

对指定实现 SHA 独立执行逻辑测试、生产构建与浏览器冒烟验收，判定工单验收标准是否全部满足；若发现真实缺陷，输出最小复现路径并交回实现方。

### 1.2 范围内

- 游戏引擎：移动、方向限制（含快速连续输入）、尾格碰撞边界、食物生成、增长与计分、墙/自身碰撞、满盘胜利、重开与难度固定。
- 存储：各难度最高分持久化、刷新恢复、损坏值与不可用存储的兜底。
- 输入：方向键 / WASD / 屏幕方向按钮、空格与按钮暂停、失焦与页面隐藏自动暂停、页面滚动防护、可编辑元素键盘行为。
- 界面与装配：开始 / 暂停 / 结束 / 胜利弹层、HUD 数值、重开与返回开始界面、计时器与监听清理。
- 构建与部署形态：`npm ci → typecheck/lint/format/test/build`，构建产物可由普通静态 HTTP 服务访问。
- 响应式：360px / 768px / 1440px 视口；Chromium 与 Firefox。

### 1.3 范围外（本轮未执行或不做）

- Safari / iOS WebKit / Android WebView（无对应浏览器可用环境，见报告"未覆盖范围"）。
- 真实移动设备触屏手势（以 Playwright 视口 + 指针事件近似）。
- 线上部署地址（工单未要求提供）。
- 性能压测、无障碍专项审计（仅覆盖键盘可达与基础语义）。

## 4. 关键测试设计说明

- **尾格边界**：分"非进食进入本步将移走的尾格（合法、长度不变）"与"进食时尾格保留（进入判碰撞）"两个方向验证，对应实现 `GameEngine.step()` 的尾格豁免逻辑。
- **快速连续输入**：同拍连按 `up + left`，断言不产生瞬时反向；转向队列上限 4，超限输入丢弃且消费顺序正确。
- **可复现随机**：逻辑用例通过可注入随机源复现食物位置；满盘场景用 4×4 棋盘 Hamiltonian 路径构造，验证 `victory` 后不再生成食物与移动。
- **异常存储**：分别模拟"损坏值（非法/负数/非数值）""写入抛异常""`localStorage` 为 null""探针失败"四类场景，断言开始、游玩、重开不被阻断。
- **计时器纪律**：以自建 `QaClock` 统计活动计时器数量，验证暂停清零、重复暂停/重开不累积、`destroy` 后监听与计时器全部释放。
- **黑盒吃食物**：冒烟脚本仅凭像素定位蛇头与食物，逐格 BFS 导航并真实吃食物，校验休闲档 +5 分且蛇身由 3 格增至 4 格。
- **速度差异**：以实测相邻移动间隔中位数比较休闲档与挑战档（期望约 200ms vs 100ms），避免固定窗口内的墙碰撞干扰计数。
- **已知行为边界（CR-01）**：审查报告 CR-01（P3）指出"HUD 按钮持有焦点时空格交还浏览器原生行为"。本计划将其作为已知行为记录用例（`CR-01 现状记录`），不计为缺陷，供产品裁决。

## 5. 通过 / 失败判定

- 逻辑用例 50/50 通过；质量门全部退出码 0；构建产物哈希与审查报告一致。
- 冒烟矩阵全部检查通过（N/N）；任一 FAIL 需给出复现条件、预期与实际结果，并判定是否构成真实缺陷。
- 发现真实缺陷：交回 `frontend_developer`，附最小复现路径；修复后针对新实现 SHA 重新审查与测试。
- 无法执行的验证（如无可用浏览器环境）必须如实记录为未覆盖或阻塞，不得标记通过。
